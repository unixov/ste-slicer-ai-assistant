# Windows smoke-test для STE Slicer AI Assistant

Этот сценарий проверяет плагин в реальном Windows-дистрибутиве STE Slicer. Он не требует публикации API-ключа в чате, issue или Git.

## 1. Подготовка

1. В репозитории выполните:

   ```text
   python tools/package_plugin.py
   ```

2. Передайте файл `dist/AIAssistant.zip` на Windows-компьютер.
3. Распакуйте папку `AIAssistant` в пользовательский каталог плагинов STE Slicer:
   `.../STE Slicer/<версия>/plugins/` или каталог, открываемый через «Справка → Показать папку конфигурации → plugins».
4. Не создавайте второй вложенный уровень `AIAssistant/AIAssistant`.
5. Полностью перезапустите STE Slicer.

## 2. Настройка API-ключа

### Вариант A: запуск из PowerShell без оператора `&`

1. Откройте PowerShell.
2. Выполните первую команду, заменив `<локальный ключ>` на свой ключ:

```powershell
$env:STE_SLICER_AI_API_KEY = "<локальный ключ>"
```

3. Запустите STE Slicer второй командой, указав настоящий путь к `.exe`:

```powershell
Start-Process -FilePath "C:\Program Files\STE Slicer\STE Slicer.exe"
```

Путь выше является примером. Если STE Slicer установлен в другом месте, укажите фактический путь из свойств ярлыка. Не вводите символы `<` и `>` буквально.

### Вариант B: без командной строки

1. Откройте **Параметры Windows → Система → О системе → Дополнительные параметры системы**.
2. Нажмите **Переменные среды**.
3. В разделе переменных пользователя создайте переменную:
   - имя: `STE_SLICER_AI_API_KEY`;
   - значение: ваш локальный API-ключ.
4. Нажмите **ОК**, закройте окна и запустите STE Slicer обычным способом через ярлык.

Не вставляйте ключ в `README.md`, скриншоты, логи или сообщения чата.

Проверьте, что при необходимости используются:

```text
STE_SLICER_AI_BASE_URL=https://api.timeweb.ai/v1
STE_SLICER_AI_MODEL=dashscope/qwen3.8-flash
```

## 3. Проверка UI и подключения

Ожидаемый результат: STE Slicer запускается без traceback, появляется stage `AI Assistant`, а внутри окна отображается sidebar с приветственным сообщением.

- Откройте stage `AI Assistant`.
- Проверьте, что поле ввода, кнопка «Отправить» и кнопка анализа видимы.
- Введите `Проверь подключение и перечисли доступные инструменты.`
- Пока идёт запрос, убедитесь, что поле и кнопки отключены.
- После ответа убедитесь, что UI снова доступен.

Если stage `AI Assistant` отсутствует:

1. Полностью закройте STE Slicer, включая его процесс в Диспетчере задач.
2. Проверьте, что файл действительно находится по пути вида:
   `...\plugins\AIAssistant\plugin.json`.
3. Убедитесь, что нет лишнего уровня `AIAssistant\AIAssistant`.
4. Запустите STE Slicer заново. Плагин должен лежать в пользовательской папке `plugins`, открытой через **Справка → Показать папку конфигурации**, а не только рядом с `.exe`.
5. Если stage по-прежнему отсутствует, сохраните версию STE Slicer, фактический путь плагина, содержимое `plugin.json` и текст ошибки из лога.

Если sidebar не появился, сохраните:

- версию STE Slicer;
- содержимое `plugin.json` и имя фактического каталога установки;
- полный текст ошибки из консоли/лога STE Slicer;
- скриншот списка stages.

## 4. Проверка чтения сцены

Загрузите небольшой STL/3MF и выполните запросы:

1. `Перечисли объекты сцены и их габариты.`
2. `Что сейчас выделено?`
3. `Покажи активную машину и основные настройки печати.`
4. `Покажи состояние backend.`

Ожидаемый результат: ответы содержат фактические данные текущей сцены. Ассистент не должен утверждать, что изменил сцену без вызова подтверждённого инструмента.

## 5. Проверка подтверждения действий

1. Запросите авторасстановку: `Автоматически расставь объекты на столе.`
2. Убедитесь, что до нажатия «Выполнить» сцена не меняется.
3. Нажмите «Отмена» и убедитесь, что операция не выполнялась.
4. Повторите запрос и нажмите «Выполнить».
5. Проверьте, что объекты расставились.

Для перемещения используйте существующий object ID из ответа `scene.list_objects`, если LLM попросит его. Проверьте Undo в самом STE Slicer.

## 6. Проверка слайсинга

1. Измените безопасный параметр печати.
2. Запросите: `Переслайсь текущую сцену.`
3. Убедитесь, что до подтверждения слайсинг не запускается.
4. Нажмите «Выполнить».
5. Запросите состояние backend и проверьте переходы `Processing`/`Done` либо понятную ошибку backend.

## 7. Проверка экспорта

### G-code

1. Сначала успешно подготовьте сцену штатным способом STE Slicer.
2. Запросите экспорт с новым абсолютным путём, например:
   `Экспортируй текущую сцену в G-code в C:\\Temp\\ai-check.gcode.`
3. До подтверждения убедитесь, что файл не создан.
4. Нажмите «Выполнить».
5. Запросите `Покажи статус последнего экспорта.`
6. Проверьте существование файла и его открываемость текстовым редактором.

### 3MF

Повторите тест с новым путём `C:\\Temp\\ai-check.3mf`. Проверьте, что файл создаётся и открывается как 3MF. В текущей версии это модельный 3MF, не полный workspace/profile project.

Проверьте защиту от перезаписи: повторный экспорт в уже существующий файл должен быть отклонён без изменения исходного файла.

## 8. Инженерные ограничения

Запрос «кронштейн под нагрузку 50 кг» должен приводить к уточняющим вопросам и явно обозначать, что настоящий FEA-анализ, heatmap напряжений и сертифицированные рекомендации пока не выполняются. Нельзя принимать текстовый ответ LLM за подтверждённый расчёт прочности.

## 9. Что прислать после проверки

Не присылайте API-ключ. Передайте только:

- версию STE Slicer и Windows;
- результат каждого раздела: `OK`/`FAIL`;
- точный текст ошибки;
- путь к логу или обезличенный фрагмент лога;
- скриншот UI, если проблема визуальная.
