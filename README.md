# STE Slicer AI Assistant

Плагин-ассистент для STE Slicer с чатом, встроенным непосредственно в интерфейс слайсера.

## Текущий статус

Первый вертикальный срез проекта включает:

- плагин формата STE Slicer/Cura API 5;
- отдельный stage `AI Assistant`;
- встроенную QML-панель в области sidebar;
- историю сообщений и поле ввода;
- кнопку анализа текущей модели;
- Python ↔ QML bridge;
- асинхронный OpenAI-совместимый HTTP-клиент без сторонних зависимостей;
- передачу OpenAI-compatible tool schemas в LLM;
- внутренний MCP-подобный JSON-RPC 2.0 слой;
- инструменты чтения сцены и настроек, авторасстановки, слайсинга и экспорта;
- безопасные значения Base URL и модели без хранения API-ключа в исходниках.

Клиент LLM подключён к панели: сетевой запрос выполняется в отдельном Qt-потоке, а tool calls проходят через MCP-реестр и затем возвращаются в LLM как результаты инструментов. Текущая панель намеренно не имитирует результаты физического расчёта.

## Установка в STE Slicer

Для воспроизводимой установки сначала соберите ZIP из корня репозитория:

```text
python tools/package_plugin.py
```

Скрипт создаёт `dist/AIAssistant.zip`. В архиве находится готовая папка `AIAssistant` без `__pycache__`, `.pyc` и скрытых файлов. Передавайте на Windows именно этот ZIP, а не содержимое каталога `plugin`.

Далее:

1. Распакуйте папку `AIAssistant` в каталог пользовательских плагинов STE Slicer.
2. Запустите STE Slicer заново.
3. В списке этапов выберите `AI Assistant`.
4. В боковой панели появится чат.

Точный каталог можно открыть через меню слайсера «Справка → Показать папку конфигурации», затем открыть подпапку `plugins`. Для пошаговой проверки используйте [`WINDOWS_SMOKE_TEST.md`](WINDOWS_SMOKE_TEST.md).

## MCP-инструменты

Внутри плагина реализован минимальный JSON-RPC 2.0 слой с методами `initialize`, `tools/list` и `tools/call`. Сейчас зарегистрированы:

- `scene.list_objects` — список загруженных mesh-объектов и их габаритов;
- `scene.get_selection` — текущий выбор пользователя в 3D-сцене;
- `settings.get` — активная машина и основные параметры печати;
- `backend.get_status` — активный backend, последнее наблюдаемое состояние и прогресс слайсинга;
- `backend.start_slicing` — запуск асинхронного переслайсинга штатным backend; требует подтверждения пользователя;
- `export.scene` — экспорт текущей mesh-сцены в новый G-code или модельный 3MF по явному пути; требует подтверждения пользователя;
- `export.get_status` — состояние последнего асинхронного экспорта;
- `scene.arrange_all` — авторасстановка объектов на столе; требует подтверждения пользователя;
- `scene.move_object` — перемещение mesh-объекта в абсолютную мировую позицию в миллиметрах; использует undoable-операцию и требует подтверждения пользователя.

MCP сейчас используется как внутренний слой плагина, а не как отдельный HTTP или stdio-сервер. Доступ к API сцены проходит через dispatcher bridge: если вызов поступает не из потока Qt-объекта, callback синхронно передаётся в главный Qt-поток с тайм-аутом. Изменяющие инструменты сначала показывают в sidebar параметры операции и выполняются только после явного нажатия «Выполнить»; «Отмена» добавляет в историю отказ без изменения сцены.

## Совместимость

Код плагина пишется с учётом Python 3.5 и PyQt5 из дистрибутива STE Slicer. Не устанавливайте отдельную версию PyQt5 внутрь папки плагина.

Основная UI-интеграция использует QML stage extension, поскольку текущий STE Slicer создаёт sidebar через `SteSlicerStage.addDisplayComponent("sidebar", ...)`. `QDockWidget` и `QWebEngineView` для базовой панели не требуются.

## Ограничения текущей версии

- требуется проверить загрузку stage и QML в целевом Windows-дистрибутиве STE Slicer;
- dispatcher защищает текущие вызовы сцены, но его поведение ещё требуется проверить в целевом Windows-дистрибутиве STE Slicer;
- `scene.move_object` реализует только абсолютную мировую позицию mesh-объекта; вложенные группы, локальные координаты и проверка попадания в build volume ещё не поддерживаются;
- `backend.get_status` сообщает состояние только после получения сигнала backend; до этого возвращает `state_known=false`;
- `backend.start_slicing` только запускает штатный асинхронный backend и не ждёт завершения; прогресс необходимо читать через `backend.get_status`;
- `export.scene` использует штатные `MeshFileHandler`/`WriteFileJob`, принимает только новый файл с расширением `.gcode` или `.3mf`, не открывает диалог и не перезаписывает существующий файл;
- G-code экспорт возможен только после успешной подготовки G-code штатным backend; writer STE Slicer читает `scene.gcode_dict`;
- 3MF экспорт в текущем adapter-е сохраняет mesh-модель, а не полный STE Slicer workspace/project profile;
- загрузка моделей, поворот, масштабирование и профили ещё не подключены;
- инженерный FEA-анализ прочности пока не выполняется;
- heatmap и adaptive infill пока не реализованы;
- эвристический ответ LLM нельзя считать сертифицированным расчётом прочности;
- автономные MCP-тесты не требуют PyQt5, а запуск stage и QML-панели требует штатного окружения STE Slicer.
- локальные проверки выполняются командами `python3 -m py_compile $(find plugin tests tools -name '*.py' -print)` и `python3 -m unittest discover -s tests -v`; упаковка проверяется командой `python3 tools/package_plugin.py`.
